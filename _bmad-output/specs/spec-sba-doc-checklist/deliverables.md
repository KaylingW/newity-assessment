# Submission Deliverables

These come from the NEWITY brief. The deadline and the submission address are still blank in the brief.

## 1. Working code
- A GitHub repo (preferred) or a zip file.
- A README with setup instructions that let a reviewer run the tool locally in under 5 minutes.

## 2. Demo video
- A 5–10 minute screen recording, kept under 10 minutes. The audience is the non-technical ops team, not engineers.
- It must cover:
  - what the tool does and how it solves the team's problem
  - a live walkthrough using the sample data
  - the scope decisions: what was built, what was cut, and why
  - a QA plan: how the tool would be tested before shipping (required even without automated tests, which are a bonus)
  - what to build in the next sprint, and why that is the priority
  - an honest self-assessment of what's good, what's rough and what to change. Claiming the tool is perfect counts against you.

## 3. AI usage log
- Evidence of AI use in each of five phases: understanding, scoping and planning, building, testing, and documentation. Any format works, such as exported chats, annotated screenshots, a recording or a written summary.
- This is graded as the most important evidence of how you work. Capture it as you go.

## Evaluation criteria
- AI used as part of the workflow throughout the lifecycle.
- Scope control.
- Thinking across the full lifecycle: testing, failure modes, V2.
- Product thinking for the actual users.
- Engineering judgment: reviewing AI output critically.
- Clear communication pitched at the right audience.
